Supported boards

One peripheral map covers the family: GD32F103 is register-identical at everything modeled, so variants differ only in flash/RAM sizes and the DBGMCU IDCODE. Timing stays instruction-budget based on every chip.

Bring-up checklist

  1. Pick the chip in the page selector (or the chip: opt) — Blue Pill default, maple_mini, nucleo_f103rb, stm32f103rc, gd32f103c8/cb/rb.
  2. Read back DBGMCU_IDCODE @ 0xE0042000 (F103 0x10016410, GD32 0x2BA01477) — one register read proves the variant is live. The page stats bar shows it after every load.
  3. Check the GPIO grid aliases (board_pins.json): Nucleo LED is D13/PA5, Maple LED is D33/PB1, Pill LED is D17/PC13.
  4. Watch the UART: Nucleo/RC Serial is USART2 (page uart_addr / test uart_addr opt selects it); Maple/Pill use USART1.
  5. DFU-layout (bootloader-offset) firmware boots via vector_table (e.g. 0x08005000 on 128K parts).

Per-board demo firmware

tests/arduino_board_demo/ compiles one sketch per FQBN (Blue Pill, Maple Mini, Nucleo-F103RB, Generic F103RC — shipped as site/arduino_board_*.elf). Each prints its board banner, blinks LED_BUILTIN and ticks; the page has a preset per board that sets chip + ELF together.

Deliberately out of scope

Maple DFU uploader / STLink probe emulation (flashing transports and debugger hardware — firmware loads directly); GD32 flash-timing / UID quirks (no observable surface); printer hardware for SKR-class boards. Full matrix in docs/BOARDS.md.
