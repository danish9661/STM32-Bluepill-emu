# GD32F103C8 — support notes

GigaDevice clone of the Blue Pill layout, register-identical to the
STM32F103 at everything modeled — so **no SVD is needed**: the variant is
a chip-table row (flash/RAM sizes + DBGMCU IDCODE `0x2BA01477`), not a new
peripheral map. Timing stays instruction-budget based (the 108 MHz top
speed changes nothing observable here).

## Silicon peripherals

Identical set to the [Blue Pill](blue-pill.md) (medium-density +
clone quirks below). Flash-timing and UID differences have no register
surface at this level and are out of scope by decision.

## Board wiring (emulator rig)

Same Blue Pill artwork and header map; LED **PC13**, `Serial` = USART1.

## Demos on this chip (28 presets)

All 24 shared presets plus the Blue Pill builds (`board_pill`,
`board_pill_echo`, `board_pill_showcase`, `board_pill_rtc`) — identical
F103 binaries run under the clone contract. (USB/OTG presets show on
every chip but only function where the peripheral is mapped — see the
matrix; covers `gd32f103c8`/`cb`/`rb`, flash 64K/128K.)

## Verification

- periph39 firmware: **39/39** on `gd32f103c8`
- GD32 boot + USART1 echo round-trip (`tests/test_chips.mjs`)

## Feature matrix (silicon vs emulator)

Silicon = GigaDevice GD32F103C8/CB/RB (medium-density, Blue Pill layout).
Emulator = this project's model on the builtin F103 map (chip-table row:
sizes + IDCODE `0x2BA01477` only — register-identical, no SVD). Statuses:
**Full** = register-level incl. IRQs/DMA/events; **Partial** = subset (see
remark); **Gap** = reads zero/lenient, no consumer; **Absent** = correctly
unmapped; **SVD-map only** = modeled, needs a custom SVD map. Other
labels (Driver/IDCODE only, Out of scope, Assumed) as marked.
Depth details: [PERIPHERALS](../PERIPHERALS.md).
